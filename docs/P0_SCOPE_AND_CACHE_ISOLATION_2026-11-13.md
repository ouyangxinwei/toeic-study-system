# P0 实施记录：统一题库范围与缓存隔离

日期：2026-11-13  
分支：`docs/phase2-data-schema-v22.1`

## 1. 本阶段目标

将当前应用允许访问和写入的题库范围统一为：

- Set：6–16
- Test：1–2
- Part：2–5

本阶段只建立应用层的数据边界与本地缓存隔离，不清空静态题库文件，不删除 Supabase 数据，不删除历史缓存，也不执行数据库迁移。

## 2. 已实施内容

### 2.1 单一范围定义

新增 `js/question-scope.js`，通过全局 `QuestionScope` 暴露：

- `setIds`、`partIds`、`testIds`
- `isSetId / isPartId / isTestId`
- `assertSet / assertPart / assertTest`
- `filterParts`
- 缓存命名空间读写方法

页面在 Supabase 和其他业务脚本之前加载该模块，避免各模块自行定义不同的范围。

### 2.2 题库加载与编辑边界

`js/question-manager.js` 已调整：

- 加载题库前校验 Set、Test。
- 静态 JSON 加载后仅保留 Part 2–5。
- Supabase 数据只有在 Part 2–5 存在有效记录时才覆盖静态题库。
- 云端预加载只建立 Set 6–16 / Test 1–2 分组，并过滤 Part 2–5。
- 新增、修改、删除题目时校验 Set 和 Part。
- 合并缓存时校验题目的 Set、Test、Part 身份，避免跨范围缓存混入。
- 保存用户数据时只保存有效 Part。

### 2.3 localStorage 缓存隔离

新缓存键格式：

`toeic_scope_v1:set{setId}:test{testId}:questions`

例如：

`toeic_scope_v1:set6:test1:questions`

隔离原则：

1. 新版本只读取新命名空间。
2. 不再回退读取旧键 `set6_test1_data` 或 `set6_data`。
3. 新版本写入时只保留 Part 2–5 的题目。
4. 旧键不会被删除、覆盖或自动迁移。
5. 删除标记等历史控制数据仍保留原键，避免本轮范围调整误删历史信息。

因此，首次进入新版本时，原有浏览器题目修改、笔记和状态不会自动出现在新缓存中。它们仍留在旧 localStorage 键中，后续需要单独设计可预览、可确认的迁移工具。

### 2.4 同步、导出与音频

- 本机上传循环改为 Set 6–16 / Test 1–2。
- 本机上传构建行时只合并新命名空间缓存和 Part 2–5 静态题目。
- 云端下载只将范围内的题目写入新缓存，备份统计也只统计范围内记录。
- 全量批量导出循环改为 Set 6–16 / Test 1–2。
- 音频上传校验 Set、Test、Part。
- 本地音频扫描只扫描新缓存，不会将旧命名空间中的音频自动迁入。
- 音频状态缓存更新使用新命名空间。

### 2.5 页面入口

- 套题选择器和录入表单只显示 Set 6–16。
- Part 筛选和录入表单只显示 Part 2–5。
- Part 2 录入允许 A–C 三个选项；Part 3–5 仍要求 A–D。
- 当前选择无效或历史偏好超出范围时，默认回退到 Set 6。
- 静态资源查询版本更新为 `v=23.0`，避免浏览器继续使用旧脚本缓存。

## 3. 重要的数据影响

| 数据位置 | 本阶段行为 | 是否删除 |
|---|---|---|
| `toeic_scope_v1:...` | 新版本读写 | 否 |
| 旧版 `setN_testN_data` | 不读取、不合并、不覆盖 | 否 |
| 旧版 `setN_data` | 不读取、不迁移 | 否 |
| 静态 `data/sets/*.json` | 仍保留原文件，加载时过滤 Part | 否 |
| Supabase `toeic_questions` | 读取/上传时应用层过滤范围 | 否 |
| Supabase 删除墓碑 | 继续读取既有记录 | 否 |
| Supabase 音频文件及关联 | 不执行批量清理 | 否 |

**注意：缓存隔离意味着新版本不会自动显示旧缓存中的本地修改。** 如果旧缓存中有尚未同步到 Supabase 的笔记、状态或新增题目，应先保留浏览器原始数据；后续 P0 补充阶段应提供只读预览和显式确认迁移，而不是直接合并。

## 6. 安全边界

本阶段没有删除任何本地旧缓存、静态 JSON、Supabase 题目、音频对象或数据库记录；没有执行 SQL；没有执行生产部署。所有云端清理必须在只读盘点、备份确认和单独迁移方案完成后再进行。

# TOEIC JSON 数据结构审查与目标规范

> 阶段：第二阶段——稳定数据结构  
> 当前运行版本：V22.0（本文件仅定义规范，不改变运行时数据）  
> 开发样本：第 6 套 Test 1  
> 目标：在开始 Supabase 完整迁移前，确定题库内容、材料、媒体资源和个人学习记录之间的稳定关系。

## 1. 本次审查范围与事实

审查对象为 `main` 分支的 `data/config.json` 与 `data/sets/set01.json` 至 `set16.json`，并对照当前题目加载、音频、笔记、导出和同步模块。

### 1.1 当前套题层级

现有 JSON 已采用以下层级，第二阶段继续保留：

```text
Set
└── tests[]
    └── Test 1 / Test 2
        └── parts[]
            └── questions[]
```

- 共 16 套模拟题。
- 每套固定包含 Test 1 和 Test 2。
- 每个 Test 固定包含 Part 1–7。
- 每份 Test 的设计容量为 200 题；每套设计容量为 400 题。
- 空题位使用空的 `questions[]`，不复制或伪造题目。
- `questionCount` 应以实际 `questions.length` 为准，不应作为独立事实来源。

### 1.3 已发现的结构问题

1. 部分题目有 `explanation`，部分题目没有；未录入解析时不能伪造内容。
2. `options` 可能是 A–C、A–D 或空对象。Part 2 使用三个选项；未完成录入的题目可能暂时为空。
3. Part 3 / 4 的共享对话或独白主要嵌在 `note` 的特殊文字标记中，前端需要解析文字来识别材料。
4. Part 6 / 7 使用 `passageGroupId` / `materialId` 关联材料；部分文章保存在组内第一道题的 `passages[]` 中。
5. 每道题当前只有一个主要 `audio` 字段，无法清晰表达“共享对话/独白音频”和“单题问题音频”是两种不同资源。
6. `note` 同时承载来源文件、ASR 校正说明、共享转录、人工确认提醒和用户笔记；语义混杂。
7. `status` 和用户笔记等学习状态与题目内容放在同一题目对象中，不利于未来按用户隔离保存。
8. 根级 `statistics` 目前包含答题数、正确数等学习统计；这类数据属于用户学习结果，不应成为公共题库 JSON 的共享状态。

## 2. 第二阶段确定的核心原则

### 2.1 固定层级，不再改变

`Set → Test → Part → Question` 是题库的固定主层级。

- `setId`：套题编号，范围 1–16。
- `testId`：Test 编号，固定为 1 或 2。
- `partId`：Part 编号，固定为 1–7。
- `questionId`：题目稳定字符串 ID。在同一 Set + Test 范围内唯一。
- 数据库和本地缓存使用复合定位键：`setId + testId + questionId`。
- Question 所属 Part 由父级 `parts[]` 决定；不要求每题重复保存 setId / testId / partId。

题号、questionId 一旦建立，不因排序、分组或展示方式变化而随意重建。

### 2.2 题目内容与个人学习数据分离

公共题目内容与个人学习进度是两类数据：

**公共题目内容**（JSON 题库 / 未来云端题库）：
- 题干、选项、正确答案、解析。
- 文章、对话、独白等共享材料。
- 题目或材料关联的图片、音频等媒体资源。
- 录入来源和编辑说明。

**个人学习数据**（当前先存浏览器本地，第三阶段再迁移到用户私有云端记录）：
- 用户选择的答案。
- 答题状态、是否掌握、是否标记复习。
- 用户自己的笔记。
- 作答次数、最近作答时间、历史答题结果。

因此，目标结构中不再把个人 `status`、个人 `note` 或用户成绩统计作为公共题目内容的权威字段。兼容旧数据时，必须先区分旧 `note` 中的材料/来源信息与真正的个人笔记，不能直接整字段搬迁。

### 2.3 材料必须独立建模

Part 3 / 4 / 6 / 7 的共享材料不再依赖 `note` 文本标记或“组内第一道题携带全文”的隐式约定。

- 每份材料有独立的 `materialId`。
- 多份材料组成一个阅读组时，使用 `groupId`。
- 每道题通过 `materialIds[]` 明确关联一份或多份材料。
- 材料的文本、标题、类型和媒体资源保存在 Part 的 `materials[]` 中。
- Part 5 每 5 题的分组仅属于展示规则，不需要虚构材料记录。
- Part 6 每篇文章可对应一个材料组和一份材料；四道题分别引用该材料。
- Part 7 单篇、双篇、三篇或多篇文章均使用显式 groupId + materialId 关系，不按题目数量推断文章边界。

### 2.4 音频与媒体资源必须区分角色

音频不是简单的“题目有一个音频链接”。

目标资源关系：

- 单题问题音频：关联到 Question。
- Part 3 对话、Part 4 独白等共享音频：关联到 Material。
- 如果同一音频服务多个问题，只保存一份资源记录，由多个题目通过材料关系引用。
- Part 1 图片、Part 3 / 4 图表或 Part 7 文档图片，也应作为明确的媒体资源关联，而不是塞入题干或 note。

资源记录至少需要能表达：
`assetId`、`mediaType`、`role`、`storageType`、`fileName`、`mimeType`，以及对应的本地路径、外部 URL 或云端 Storage 路径。
临时签名 URL、浏览器 Object URL 不作为永久数据保存。

## 3. 目标 JSON 结构

以下是目标结构示意。它是第二阶段的规范草案；现有 JSON 在完成兼容转换前继续按 V22.0 格式读取，不在本次文档提交中批量改写题库。

```json
{
  "schemaVersion": "2.0",
  "setId": 6,
  "setName": "第6套模拟题",
  "lastUpdated": "2026-11-12T00:00:00.000Z",
  "tests": [
    {
      "testId": 1,
      "testName": "Test 1",
      "totalQuestions": 200,
      "parts": [
        {
          "partId": 3,
          "partName": "Part 3 - Conversations",
          "partType": "listening",
          "questionCount": 39,
          "materials": [
            {
              "materialId": "set06-t1-p3-m01",
              "groupId": "set06-t1-p3-g01",
              "materialType": "conversation",
              "title": "",
              "content": "共享对话转录……",
              "assets": [
                {
                  "assetId": "audio-set06-t1-p3-m01",
                  "mediaType": "audio",
                  "role": "shared_material",
                  "storageType": "local",
                  "fileName": "conversation.mp3",
                  "mimeType": "audio/mpeg",
                  "path": "audio/..."
                }
              ],
              "source": {
                "fileName": "原始音频文件名.mp3",
                "transcriptionStatus": "needs_review"
              }
            }
          ],
          "questions": [
            {
              "questionId": "6-3-032",
              "title": "Where do the speakers most likely work?",
              "options": {
                "A": "Option A",
                "B": "Option B",
                "C": "Option C",
                "D": "Option D"
              },
              "correctAnswer": "",
              "explanation": "",
              "materialIds": ["set06-t1-p3-m01"],
              "assets": [
                {
                  "assetId": "audio-set06-t1-p3-q032",
                  "mediaType": "audio",
                  "role": "question_prompt",
                  "storageType": "local",
                  "fileName": "questions.mp3",
                  "mimeType": "audio/mpeg",
                  "path": "audio/..."
                }
              ],
              "editorialNote": ""
            }
          ]
        }
      ]
    }
  ]
}
```

说明：
- 上面仅展示一个 Part 3 的结构例子，不代表本次要把 200 道题改成示例内容。
- 实际文件仍保留完整 7 个 Part；示意中省略了其他 Part 和 Test 2。
- `correctAnswer` 暂时允许空字符串，表示尚未录入或尚待人工确认；不得自动猜答案。
- `explanation` 可缺省或为空，只有有可靠依据时才录入。
- `options` 按实际题型允许 A–C 或 A–D；录入未完成时允许空对象，但完成题目必须符合对应 Part 的选项要求。
- `questionCount` 是可重新计算的冗余字段，实际题数以 `questions.length` 为准。
- `totalQuestions` 表示该 Test 的设计容量，不表示已经录入的题数。

## 4. 目标字段定义

### 4.1 Set

| 字段 | 类型 | 要求 | 说明 |
|---|---|---|---|
| schemaVersion | string | 必须 | JSON 结构版本 |
| setId | number | 必须 | 1–16 |
| setName | string | 必须 | 套题名称 |
| lastUpdated | ISO datetime | 必须 | 题库内容最后更新时间 |
| tests | array | 必须 | 固定包含 Test 1、Test 2 |

公共题库不保存用户个人的 totalAnswered / correct / wrong / reviewed 统计。

### 4.2 Test / Part

| 层级 | 字段 | 说明 |
|---|---|---|
| Test | testId | 固定 1 或 2 |
| Test | testName | Test 1 / Test 2 |
| Test | totalQuestions | 设计容量，当前为 200 |
| Test | parts | 固定包含 Part 1–7 |
| Part | partId | 1–7 |
| Part | partName | 英文 Part 名称 |
| Part | partType | listening 或 reading |
| Part | questionCount | 根据 questions.length 计算 |
| Part | materials | 共享材料数组，可为空 |
| Part | questions | 题目数组 |

### 4.3 Question

| 字段 | 类型 | 说明 |
|---|---|---|
| questionId | string | Set + Test 范围内稳定唯一 |
| title | string | 题干或问题 |
| options | object | A–C、A–D 或录入中的空对象 |
| correctAnswer | string | 正确选项；未确认时为空字符串 |
| explanation | string | 可选解析 |
| materialIds | string[] | 关联的共享材料，可为空 |
| assets | array | 单题图片、问题音频等媒体资源 |
| editorialNote | string | 录入说明、人工校对提醒，不用于存放用户个人笔记 |

### 4.4 Material

| 字段 | 类型 | 说明 |
|---|---|---|
| materialId | string | 单份材料唯一 ID |
| groupId | string | 同一篇/组材料的分组 ID |
| materialType | string | conversation、talk、passage、image、chart、document 等 |
| title | string | 材料标题，可为空 |
| content | string | 转录、文章或材料正文 |
| assets | array | 该材料共用的音频、图片等资源 |
| source | object | 原始文件名、来源及转录校对状态 |

### 4.5 Asset

| 字段 | 说明 |
|---|---|
| assetId | 媒体资源稳定 ID |
| mediaType | audio / image / document |
| role | question_prompt / shared_material / stimulus 等 |
| storageType | none / local / remote / cloud |
| fileName | 原始文件名 |
| mimeType | MIME 类型 |
| path | 本地资源路径，仅本地模式使用 |
| url | 外部资源 URL，仅 remote 模式使用 |
| storagePath | 云端 Storage 对象路径，仅 cloud 模式使用 |

本地、远程和云端是同一个资源模型的不同存储方式；不把临时播放地址写回 JSON。

## 5. 个人学习记录目标结构

个人学习数据与公共题库分离。当前阶段先继续使用浏览器本地存储；第三阶段再将相同逻辑映射到 Supabase 用户私有表。

单条学习记录建议使用以下字段：

```json
{
  "setId": 6,
  "testId": 1,
  "partId": 5,
  "questionId": "6-5-101",
  "selectedAnswer": "B",
  "status": "correct",
  "userNote": "需要复习介词用法",
  "attemptCount": 2,
  "lastAnsweredAt": "2026-11-12T00:00:00.000Z",
  "updatedAt": "2026-11-12T00:00:00.000Z"
}
```

- 一条记录通过 `setId + testId + questionId` 对应一道题。
- `status`、`selectedAnswer`、`userNote`、作答次数和时间属于用户数据。
- 题目内容更新不应清除用户学习记录。
- 删除题目时，后续需要明确其学习记录的保留或清理策略；不得静默丢失历史成绩。

## 6. Part 1–7 关联规则

| Part | 题目与材料关系 | 规范 |
|---|---|---|
| Part 1 | 一题 + 图片刺激 | 图片作为题目资产；问题音频按实际来源关联 |
| Part 2 | 一题 + 问题音频 | 每题独立关联音频；选项通常 A–C |
| Part 3 | 一段对话 + 多道题 | 对话作为 Material；问题通过 materialIds 引用 |
| Part 4 | 一段独白/公告 + 多道题 | 独白作为 Material；问题通过 materialIds 引用 |
| Part 5 | 单题句子填空 | 不需要共享 Material；每 5 题分组仅用于展示 |
| Part 6 | 一篇文章 + 4 道题 | 文章作为 Material；四题分别引用 |
| Part 7 | 一组单篇/双篇/多篇文章 + 多道题 | 每篇文章独立 materialId，同组共享 groupId；题目可引用一篇或多篇材料 |

题目数量和组内数量不决定材料边界。材料边界必须由显式 ID 表达。

## 7. 旧结构兼容与迁移规则

在正式采用 schemaVersion 2.0 前，必须实现一次明确的兼容转换：

1. 读取旧版 Set / Test / Part / Question 结构。
2. 把 Part 3 / 4 的共享转录从 `note` 特殊标记中提取到 `materials[]`；同一组只生成一份材料。
3. 把 Part 6 / 7 的 `passages[]` 提取成独立 Material；保留原有 passageGroupId / materialId 的语义。
4. 为每道题生成或保留稳定的 `materialIds[]`，不得通过题号数量猜文章边界。
5. 将来源文件名、ASR 说明和人工校对提醒迁移到 `source` / `editorialNote`，不能丢失。
6. 将真正的个人笔记、status 和答题记录迁移到个人学习数据；若旧字段无法判断是来源说明还是用户笔记，必须保留原文并标记待人工确认，不得擅自删除。
7. 将旧 `audio.type` / `path` / `url` / `storagePath` 转换为统一 assets 表达；不复制音频二进制，不改变 Storage 文件。
8. 转换前生成原始 JSON 备份；转换后能回滚到旧结构。
9. 转换后核对每个 Set + Test 的题数、questionId、答案、解析、材料关系及音频引用。

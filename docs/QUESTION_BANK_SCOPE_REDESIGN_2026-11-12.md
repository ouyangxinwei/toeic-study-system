**项目：** [toeic-study-system](https://github.com/ouyangxinwei/toeic-study-system)  
**工作分支：** `docs/phase2-data-schema-v22.1`  
**关联 PR：** [#4 — feat: add TOEIC JSON validator and safe material converter](https://github.com/ouyangxinwei/toeic-study-system/pull/4)  
**文档状态：** 已确认的产品范围决策与实施分析；尚未执行数据删除、覆盖、云端迁移或部署。

> 本文是后续代码和数据调整的唯一范围依据之一。用户已明确表示数据库已自行备份。本文仍要求实施时保留可追溯备份与执行报告；“已备份”不等于可以跳过迁移前核对。

## 1. 本次重构的最终决定

题库不再以“16 套完整 TOEIC 试卷”为目标，而改为“保留 Set 6–16 的编号空间、其中 Set 16 专门作为开发测试数据”。

### 1.1 Set 范围

| Set | 最终状态 | 用途 |
|---|---|---|
| Set 1–5 | 从正式系统题库中彻底移除 | 不再显示、不再练习、不再迁移、不再维护 |
| Set 6–15 | 保留套题编号与空结构，清空全部题目内容 | 未来正式练习题的录入位置 |
| Set 16 | 保留编号，全部内容替换为最新 Set 6 的题库内容 | 固定开发 / 验收测试数据 |

具体解释：

- Set 6 这个编号继续存在，但内容清空。
- Set 7–15 同样保留编号，但内容全部清空。
- 原来最新的 Set 6 题库内容复制到 Set 16。
- Set 16 原有内容不再保留在活动题库中；其旧内容由既有备份 / Git 历史承担恢复依据。
- Set 16 是接近真实题目结构的测试数据，不应在 UI、文档或统计中误称为官方 TOEIC 真题。
- 当前正式活动题库的 Set 编号范围是 6–16，共 11 个编号；其中 6–15 是空白题套，16 是测试样本。

### 1.2 Part 范围

所有保留的套题（包括 Set 16）只支持以下四个 Part：

| Part | 最终状态 | 题型 |
|---|---|---|
| Part 1 | 移除 | Photographs |
| Part 2 | 保留 | Question-Response |
| Part 3 | 保留 | Conversations |
| Part 4 | 保留 | Talks |
| Part 5 | 保留 | Incomplete Sentences |
| Part 6 | 移除 | Text Completion |
| Part 7 | 移除 | Reading Comprehension |

未来新增题目、材料、答案、音频、导入文件、导出文件和练习功能，均只能针对 Part 2–5。

### 1.3 目标数据概览

| 范围 | 活动题库中的预期状态 |
|---|---|
| Set 1–5 | 不存在于活动题库 |
| Set 6–15 / Test 1 | Part 2–5 均为空 |
| Set 6–15 / Test 2 | Part 2–5 均为空 |
| Set 16 | 由最新 Set 6 数据复制而来；仅含 Part 2–5 |

Set 6–15 的空结构应保留稳定的 Set/Test/Part 层级，空题数组使用 `[]`，空材料数组使用 `[]`，不得用虚构题目填充。若应用实际只启用 Test 1，也不能因此把 Test 2 的数据误合并到 Test 1；两者仍按既有 Test 维度隔离。

## 2. 为什么采用这套安排

1. **降低题库维护成本：** 不再维护 Part 1 图片、Part 6/7 长文章及其复杂分组。
2. **降低录入成本：** 未来只需维护 Part 2–5。
3. **保留未来扩充空间：** Set 6–15 的编号仍在，不需要以后重新设计套题编号。
4. **建立稳定测试样本：** Set 16 使用一套较完整、接近实际使用形态的数据，供功能开发和人工验收。
5. **避免测试数据与练习数据混杂：** 空白的 Set 6–15 用于未来正式练习；Set 16 固定用于开发验证。
6. **避免重复迁移：** 旧 Set 1–5 以及 Part 1/6/7 不再投入转换和云端迁移工作。

## 3. 对现有系统的影响评估

本次变更不只是删除 JSON 中的题目。现有应用曾按 1–16 套、Part 1–7、每套 Test 1 / Test 2、Supabase 同步、音频存储和本地缓存设计，因此需要检查所有依赖这些范围的代码。

### 3.1 配置文件与套题导航

**可能涉及：**

- `data/config.json`
- 套题选择下拉框、套题卡片和导航组件
- 首页统计、题目总数和进度显示
- 默认套题、上/下一套切换逻辑
- 任何假定 Set 编号从 1 连续开始的循环

**需要调整：**

- 活动套题列表只显示 Set 6–16。
- Set 6–15 显示为空白题套；不得因为没有题目就从选择器中消失。
- Set 16 显示为“开发测试数据”或类似明确标识。
- 配置中的“活动套题数量”和“最大 Set 编号”应区分。活动套题数量是 11，最大编号是 16；不能简单把 `total=11` 后继续用 1..11 生成 Set 列表。
- Part 配置仅保留 2、3、4、5。
- 不再显示 Part 1、6、7 的导航、题量、进度或空状态入口。
- 首页统计应只统计当前活动范围；旧缓存或云端遗留记录不能让已移除的 Set/Part 重新出现在统计中。

### 3.2 题库 JSON 与数据结构

**可能涉及：**

- `data/sets/set01.json` 至 `set16.json`
- Set/Test/Part/Question/Material 的嵌套结构
- JSON 导入、导出与本地加载
- 题目 ID、材料 ID、音频引用

**需要调整：**

- 活动数据不再包含 Set 1–5。
- Set 6–15 保留 Set 元数据、Test 层级及 Part 2–5 空数组。
- Set 16 只包含 Part 2–5。
- Part 1/6/7 对应的题目、材料和资源引用均不得进入新活动数据。
- Part 3/4 的共享材料关系继续保留，因为它们属于新范围；Part 2/5 不应被强制套用长材料结构。
- 清理旧数据时必须同时检查材料数组、嵌套 passages、音频字段、资源数组和任何孤立引用，而不能只删除 Part 节点。
- 题目 ID 应在 Set 16 内保持唯一。复制 Set 6 到 Set 16 时，必须按应用实际 ID 规则检查冲突；如 ID 本身包含 Set 编号，应统一转换为 Set 16 的 ID，并同步更新所有引用，不能只改题目 ID 而漏掉 materialId / audio 引用。

### 3.3 Part 3 / Part 4 材料管理

本次范围调整后，材料模型仍然需要，但只需要保留听力材料场景：

- Part 3：一段对话关联对应的多道题。
- Part 4：一段独白 / 短文关联对应的多道题。
- Part 3 / Part 4 的共享 transcript、音频和题目引用需要保留。
- Part 6 / Part 7 的 passage、document_set、文章左右分栏等逻辑不再属于正式题库需求。
- 如果通用 Material 模型仍被 Part 3/4 使用，不应整体删除 Material；应删除的是 Part 6/7 专用材料类型和相关 UI / 转换逻辑。

### 3.4 题目练习、答题和成绩

**需要检查：**

- Part 导航与练习入口
- 题目数量和答题进度
- 单题答题、答案判定、解析展示
- Test 完成判定和分数计算
- 按 Part 统计正确率、错题数、完成率
- 练习结果页、历史记录和复习入口

**影响与要求：**

- 练习流程只遍历 Part 2–5。
- 空白 Set 6–15 应显示“暂无题目 / 尚未录入”，不能显示为已完成，也不能因 0 题产生除零错误或 100% 正确率。
- Set 16 的完成判定应以实际存在的题目为准，不能继续使用旧的 200 题固定假设。
- 如果成绩计算原本假设完整 TOEIC 200 题或 Listening/Reading 各 100 题，需要改为按当前实际题目和 Part 2–5 的业务规则计算；不能把新题库分数直接标记为官方 TOEIC 标准分。
- 若历史学习记录引用 Set 1–5 或 Part 1/6/7，旧记录不应被错误映射到其他题目。应明确标记为历史 / 不在当前活动范围，或在 UI 中不展示；不要更改其原始题目 ID。

### 3.5 搜索、错题、收藏和学习记录

**需要检查：**

- 全局搜索
- 错题本 / 待复习列表
- 收藏和掌握状态
- 个人笔记
- 学习历史和每题答题记录
- 按 Set / Test / Part 筛选的所有页面

**风险：**

用户学习记录通常通过 `set_id + test_id + question_id` 或类似复合键关联题目。删除活动题库数据不代表这些个人记录会自动安全删除。若保留旧记录但题目已经不在活动题库，页面可能出现“找不到题目”的孤立记录。

**建议处理：**

- 不把旧题目的个人记录自动转绑到 Set 16。
- Set 6 复制到 Set 16 后，Set 16 应作为新的题目身份；不能继承 Set 6 原有用户答题状态、错题次数或收藏状态。
- Set 1–5 / Part 1、6、7 的旧记录可保留在历史备份或历史记录层，不参与当前练习和统计。
- 搜索、错题本、复习列表只显示能在当前活动题库中解析的 Set 6–16 / Part 2–5 题目；无法解析的旧记录应被安全过滤或标注为历史记录，不能导致整个页面报错。
- 个人学习状态与固定题库内容仍应保持分离。

### 3.6 音频与 Supabase Storage

**可能涉及：**

- `toeic_questions` 等题库表
- 音频索引表、音频引用关系
- Supabase Storage 的 `toeic-audio` Bucket
- 删除题目 RPC、音频引用计数和清理任务
- 浏览器 IndexedDB 音频缓存

**重要风险：**

数据库备份不一定包含 Storage Bucket 中的实际音频文件。数据库记录、Storage 对象和 IndexedDB 缓存是不同层次。不能因为 Set 1–5 或 Part 1/6/7 不再使用，就直接批量删除所有相关 Storage 对象。

**建议处理：**

- Set 16 复制时，检查 Part 2–4 的音频引用是否仍有效。
- 如果音频索引使用题目 ID / Set ID 关联，复制时要建立 Set 16 对应的引用关系。
- 对共享音频先统计全局引用数；只有确认没有其他活动题目引用，且备份策略覆盖该文件后，才考虑删除旧 Storage 文件。
- 不要仅因旧 Set/Part 记录被删除就直接删除共享音频。
- 清理浏览器缓存时，只清理明确属于旧题目的缓存键；不得误删 Set 16 仍在使用的音频。
- 重新登录、跨设备同步和音频播放必须使用 Set 16 的新关联，不得继续依赖 Set 6 已清空的活动记录。

### 3.7 Supabase 数据库、RLS 与同步

当前项目已有 Supabase 登录、题库读写、Test 维度、音频索引和用户偏好等历史能力。此次重构可能影响：

- Set 编号和 Part 编号约束
- `set_id + test_id + question_id` 唯一键
- 题库查询、上传、下载和分页
- 题目删除与音频清理 RPC
- 用户偏好中的当前 Set / Test
- RLS 策略与共享题库访问

**实施要求：**

1. 先盘点现有表、约束、索引、触发器和 RPC；不要凭旧 SQL 文件推断线上数据库现状。
2. 活动查询只返回 Set 6–16、Part 2–5。
3. Set 6–15 的活动题目记录清空；Set 16 写入复制后的测试题目。
4. Set 1–5 的旧题目记录从活动题库移除；如需保留审计历史，应通过备份或独立历史存档，不应继续混入活动查询。
5. 约束应允许 Set 6–16 和 Part 2–5；避免把“活动套题数量 11”错误作为最大 Set ID。
6. RLS 负责访问权限，不应被本次范围过滤替代；不能为了隐藏题目而放宽访问控制。
7. 上传 / 下载同步逻辑必须防止旧浏览器缓存把 Set 1–5 或 Part 1/6/7 重新写回云端。
8. 同步前应验证导入数据范围；不符合新范围的数据应报告并拒绝，不应静默混入。
9. 本次文档提交不执行任何 SQL，也不改变 Auth、RLS 或 Storage 配置。

### 3.8 导入、导出和数据校验工具

当前仓库已有：

- `scripts/validate_question_bank.py`
- `scripts/convert_legacy_materials.py`

它们的既有目标覆盖 16 套及 Part 1–7，需要按新范围重设。

**校验器目标：**

- 活动 Set 允许值为 6–16。
- 活动 Part 允许值为 2、3、4、5。
- Set 1–5 出现在活动数据时报告范围错误。
- Part 1、6、7 出现在活动数据时报告范围错误。
- Set 6–15 可以是合法空题套；不能将空题数组误判为损坏。
- Set 16 必须满足测试样本的基本结构要求，但题目数量应从真实数据计算，不应在没有确认完整性前硬编码为 200。
- 检查 Set 16 的题目 ID、材料 ID、音频引用和 Test 隔离。
- 校验器必须只读，不自动删除或修复源数据。

**转换器目标：**

- 不再为 Part 6 / Part 7 生成材料。
- 只保留 Part 3 / Part 4 的共享 transcript 转换能力（如仍需要旧格式兼容）。
- 对 Part 2 / Part 5 不执行无必要的材料转换。
- 不再对 Set 1–5 执行迁移。
- Set 6 的数据复制到 Set 16 应作为独立、可预览、可核对的迁移步骤，不应与普通材料转换混为一个不可审查操作。

## 4. Set 16 的复制规则与数据质量门槛

Set 16 是后续开发的固定测试夹具（test fixture），因此必须稳定、可重复使用，不能只复制一个字段不完整的临时导出文件。

### 4.1 数据来源

优先使用仓库 / 当前系统中最新、完整、权威的 Set 6 原始题库数据作为来源。

**特别注意：** 2026-11-12 检查的文件 `set06_test1_wrong_questions_20261112_1720.json` 虽然包含 200 道题，但检查结果为：

- 200 道题的 `correctAnswer` 均为空；
- 69 道题的 `options` 为空；
- Part 7 没有可用于建立真实阅读材料的完整正文；
- 该文件属于错题导出形态，不能仅凭文件名或题目数量认定它是可直接替换 Set 16 的完整题库。

因此，该导出文件只能作为结构参考或待补充来源，不能在未补齐 / 未确认答案、选项、音频和材料的情况下直接作为最终测试数据。正式复制前必须确认最新 Set 6 的权威来源文件，以及 Test 1 / Test 2 的实际数据范围。

### 4.2 复制时必须保留的内容

在新范围内复制：

- Part 2、Part 3、Part 4、Part 5 的题目内容；
- 题干、选项、正确答案、解析、必要备注；
- Part 3 / Part 4 的共享 transcript；
- 有效音频引用和资源元数据；
- Test 维度与分组关系；
- 可用于展示和答题的必要元数据。

### 4.3 复制时必须排除的内容

- Part 1、Part 6、Part 7 的所有题目和材料；
- 已不再使用的阅读 passages / document_set 材料；
- Set 6 原有的用户个人作答状态、错题状态、收藏、学习历史；
- 不能确认有效的孤立音频引用；
- 任何 Set 1–5 的活动题库内容。

### 4.4 Set 16 的身份与标记

- Set 16 的题目身份属于 Set 16，不能继续以 Set 6 的活动题目身份写入。
- 如题目 ID 编码包含 Set 编号，复制时应按规则生成 Set 16 ID，并同步重写材料引用。
- 页面应明确标记“开发测试数据”，避免被当作用户正式练习进度或官方真题成绩。
- 测试数据应固定且可重复初始化；普通用户练习操作是否写入个人记录，按现有学习记录设计处理，但不应反向修改测试夹具原始内容。
- 后续若 Set 6–15 录入真实新题，不能覆盖 Set 16 测试数据。

## 5. 建议的实施阶段

按“先盘点、再本地数据、再功能、最后云端”的顺序执行，避免同时改动多个层次。

### 阶段 A：冻结范围与代码盘点

- [ ] 将本文作为正式范围基线。
- [ ] 搜索全仓库所有 Set 1–16、Part 1–7 的硬编码与循环。
- [ ] 搜索题目数量 200 / 400、Part 数量 7、Set 起始编号 1 等假设。
- [ ] 盘点本地 JSON、浏览器 localStorage、IndexedDB、Supabase 表和 Storage 引用。
- [ ] 标注所有受影响文件，形成实施清单。
- [ ] 不在盘点阶段删除或覆盖任何数据。

## 6. 重点风险与防护措施

| 风险 | 可能表现 | 防护措施 |
|---|---|---|
| 旧范围硬编码未清理 | 页面仍显示 Set 1–5 或 Part 1/6/7 | 全仓库搜索并逐项更新 |
| Set 数量与编号混淆 | 只显示 Set 6–11，遗漏 Set 12–16 | 用显式 Set ID 列表，不使用 1..total 推算 |
| Set 16 复制不完整 | 答案、选项、材料或音频缺失 | 复制前预览，逐字段核对；不使用不完整错题导出作为唯一来源 |
| 题目 ID 冲突 | Set 16 编辑 / 同步覆盖 Set 6 | 复制时生成正确目标 ID，并检查复合唯一键 |
| 材料引用断裂 | Part 3/4 对话无法显示 | 同步更新 materialId 和材料对象 |
| 个人学习记录串题 | Set 6 历史错题被错误显示在 Set 16 | 不复制用户学习状态；历史记录按原身份保留 |
| 旧缓存回流 | 删除后再次同步又出现旧题 | 更新缓存版本 / 迁移策略，上传前校验范围 |
| 音频误删 | Set 16 或其他题目无法播放 | 先查全局引用，不直接批量删除 Storage 对象 |
| 统计计算错误 | 空题套题出现 NaN 或虚假正确率 | 对 0 题显式显示未录入，不参与完成率分母 |
| 云端与本地不一致 | 页面数据与 Supabase 不同 | 先迁移预览，再按固定顺序写入和核对 |
| 误称官方真题 | 测试数据成绩被误读为官方成绩 | UI 明确标记开发测试数据，不声称官方真题 |

### 2.3 旧材料转换工具（初步实现）

- 已增加 `scripts/convert_legacy_materials.py`。
- 已加入对应单元测试文件和 README 使用说明。
- 设计目标：
  - Part 3 / Part 4：将重复的共享对话文本整理为 Material.transcript。
  - Part 6：将重复文章正文整理为 Material.passages[]。
  - Part 7：将组内 passages 提升为 document_set 类型 Material，并将旧字段 `text` 规范化为 `content`。
  - 保留题目 ID、题目内容、选项、答案、解析、音频、状态、时间戳及已有分组关系。
- 默认模式只生成预览和独立转换结果，不覆盖源文件。
- 正式替换需要显式使用 `--apply --confirm-replace REPLACE`，并执行哈希检查和自动备份。

**注意：** 转换器和相关单元测试尚未确认在本地实际运行通过，因此目前只能视为“代码已加入，待执行验证”，不能标记为已验证完成。

## 6. 建议的下一步顺序

下次继续开发时，按以下顺序推进，避免同时改动数据结构、运行时和云端：

1. **先执行现有校验器与转换器测试**，确认仓库中的工具能在实际项目环境运行。
2. **生成 Set 06 Test 1 转换预览**，重点审查 Part 3 / 4 / 6 的共享材料关系。
3. **处理 Part 7 正文缺失问题**，先标记缺失，不自动编造。
4. **核对新旧数据结构映射**，确认不会丢失题目 ID、选项、答案、解析、音频和状态。
5. **完成本地页面适配与代表性人工测试**。
6. 本地稳定后再进入云端架构，最后进行 16 套题库批量迁移。
